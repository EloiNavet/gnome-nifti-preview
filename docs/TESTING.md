# Testing

All test data are synthetic phantoms generated by `reference/src/nifti_preview_ref/synthetic.py`
(`nifti-preview-ref make-fixtures DIR`), DICOM files written by the tests, a few
codec streams made from synthetic images (`backend/src/formats/dicom/testdata/`),
a short bzip2 stream (`backend/src/formats/testdata/`) and the test files that ship
with pydicom. No subject data is downloaded.

CI runs both the Rust tests and Clippy with stable and the Rust 1.85 MSRV, with
and without default features, for the backend and for nitty (`-p nitty`). Local
lint: `cargo clippy --workspace --all-targets --locked -- -D warnings` (and again
with `--no-default-features`).

The shell tests run in a throw-away home folder with every XDG directory inside
it (`tests/lib/home.sh`): they never touch the real home folder, its
`mimeapps.list` or its running previewer.

The real-Sushi test needs `gnome-sushi gjs xvfb xdotool imagemagick x11-utils
dbus-x11 procps python3`. CI runs it on Ubuntu 24.04 (Sushi 46), 26.04 (Sushi 50)
and 26.10 (Sushi 51, allowed to fail).

## Checking on your desktop

1. Run the install command from the README (or `./install.sh` from a clone).
2. In Files, select a `.nii.gz` and press Space: three slices and the metadata appear.
3. Scroll over each view, click in one view, press O, L, C, then V and Page Down; check the R/L letters.
   On a segmentation, a click shows the label and its volume. On a NIfTI-MRS
   file, the spectrum appears; press L and Z.
4. Press Space: the preview closes; `pgrep -x nifti-preview` prints nothing.
5. Press Space on a PDF and a PNG: their usual previews still appear.

## Checking nitty in real terminals

1. In GNOME Terminal or Ptyxis: `nitty -p IMAGE` prints three views in half blocks;
   `nitty IMAGE` opens the viewer (the status bar says `blocks truecolor`); move with the
   arrows, Page Up/Down, O, L, Tab, the mouse; resize the window; Ctrl-Z then `fg`; `q`.
   The prompt comes back as it was (`stty -a` unchanged).
2. In Kitty, WezTerm, Konsole, foot or xterm (`xterm -ti vt340`): the status bar names the
   protocol (`kitty`, `iterm2`, `sixel`) and the views are pictures.
3. In tmux, then `ssh localhost` and run it there: half blocks (or Sixel with a tmux that
   draws it); `NITTY_PROBE_MS` bounds the wait for the terminal's answers.
4. `NITTY_TIMING=1 nitty IMAGE 2> timing.log`: the time and bytes of each frame.
5. A DICOM folder, a 4D series (`,` `.`), a segmentation (Tab: names and cm³), a spectrum.
